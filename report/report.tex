\section{Glossary of the Haskell Type System}
Before investigating kinds, we briefly explain the most important definitions in Haskell's type system and make example(s).
\subsubsection*{Type}
A type classifies values and expressions; it describes what kind of data something is and which operations are valid on it.
\begin{lstlisting}
    Int, Bool, Char
    [Int]
    int -> Bool
    Maybe Int
\end{lstlisting}
\subsubsection*{Type Signature}
A type signature is an explicit annotation of an expression’s type.
\begin{lstlisting}
    not :: Bool -> Bool
\end{lstlisting}
\subsubsection*{Type Variable}
A type variable is a placeholder for an unknown type, enabling polymorphism. Usually written \texttt{a}, \texttt{b}, \texttt{t}, etc.
\begin{lstlisting}
    id :: a -> a -- Here the type signature of "id" contains type variables
\end{lstlisting}
\subsubsection*{(Parametric) Polymorphism}
Parametric polymorphism means code works uniformly for any type, without inspecting that type.
\begin{lstlisting}
    length :: [a] -> Int
\end{lstlisting}
\subsubsection*{Type Constructor}
A type constructor is something that builds new types from type parameters (a "type-level function").
\begin{lstlisting}
    [] :: Type -> Type
    Maybe :: Type -> Type
    Either :: Type -> Type -> Type
\end{lstlisting}
\subsubsection*{(Data) Constructor}
A data constructor builds values, not types.
\begin{lstlisting}
    Just :: a -> Maybe a
    Nothing :: Maybe a
\end{lstlisting}
\subsubsection*{Type Class}
A type class defines a set of operations (methods) and laws that a type can implement. It’s like an interface/contract at the type level.
\begin{lstlisting}
    class Eq a where
        (==) :: a -> a -> Bool
\end{lstlisting}
\subsubsection*{Type Constraint}
A type constraint restricts a type variable to types that are instances of some type class(es). Written before \texttt{=>} in a type signature.
\begin{lstlisting}
    (==) :: Eq a => a -> a -> Bool
    foo :: (Eq a, Show a) => a -> String
\end{lstlisting}
\subsubsection*{Constrained Polymorphism}
When a function is polymorphic but only for types satisfying constraints (type classes), it’s constrained (often called ad-hoc polymorphism).
\begin{lstlisting}
    show :: Show a => a -> String
\end{lstlisting}


\section{Kinds in Haskell}
Haskell offers besides a classical typesystem a "typesystem of a typesystem", also called \textit{kinds} (i.e. kind of a type or type of a type). In GHCI, the interactive haskell interpreter, we can use the \texttt{:t} command to check the type of a previously declared variable:
\begin{lstlisting}
    ghci> x = 42 :: Int
    ghci> :t x
    x :: Int
\end{lstlisting}
Now, the type \texttt{Int} has the following kind, which we can check using the \texttt{:k} command:
\begin{lstlisting}
    ghci> :k Int
    Int :: *
\end{lstlisting}
In contrast, we can check the kind of a type constructor such as \texttt{Maybe}:
\begin{lstlisting}
    ghci> :k Maybe
    Maybe :: * -> *
\end{lstlisting}
\texttt{Maybe} is a type constructor, meaning it takes an additional type as an argument, which will then produce the kind:
\begin{lstlisting}
    ghci> :k Maybe Int
    Maybe Int :: *
\end{lstlisting}
More complex kinds are also possible:
\begin{lstlisting}
    ghci> :k Either
    Either :: * -> * -> *
    ghci> :k (->)
    (->) :: * -> * -> *
\end{lstlisting}

\subsection{Higher-kinded Types}
A higher-kinded type is a type constructor taking a type constructor as an argument:
\begin{lstlisting}
    ghci> :k Functor
    Functor :: (* -> *) -> Constraint
\end{lstlisting}
Here \texttt{Constraint} is a the kind of type constraints. We can test the \texttt{Functor} kind by supplying different types or type constructors:
\begin{lstlisting}
    ghci> :k Functor Maybe
    Functor Maybe :: Constraint
    ghci> :k Functor Int

    <interactive>:1:9: error:
        - Expected kind '* -> *', but 'Int' has kind '*'
        - In the first argument of 'Functor', namely 'Int'
        In the type 'Functor Int'
\end{lstlisting}
Under the hood GHC, the Haskell Compiler, treats kinds as types, meaning internally mostly the same procedures are used to check the correctness of types and kinds.


\subsection{Other Kinds}
\subsubsection*{DataKinds}
With \texttt{DataKinds}, constructors can be used as types.
\begin{lstlisting}
    {-# LANGUAGE DataKinds #-}
    import Data.Kind (Type)

    data Nat = Z | S Nat
\end{lstlisting}
Now, new types or type constructors are created for the constructors, prefixed by \texttt{'}:
\begin{lstlisting}
    Nat :: *
    'Z :: Nat
    'S :: Nat -> Nat
\end{lstlisting}
\subsubsection*{PolyKinds}
With \texttt{PolyKinds}, GHC can infer kind-polymorphic definitions.
\begin{lstlisting}
    {-# LANGUAGE PolyKinds #-}
    data Proxy (a :: k) = Proxy
\end{lstlisting}
Here \texttt{k} is a kind variable, and the constructor is kind-polymorphic:
\begin{lstlisting}
    Proxy :: forall k. k -> *
\end{lstlisting}
This is similar to polymorphic types, but at the kind level.


\section{Kinds and Types in F\#}
Haskells kind system is similar to the arity of type constructors in F\#. In F\#, generic type definitions are most similar to Haskell's type constructors and parametric polymorphism:
\begin{lstlisting}
    int // no parameters
    'T option // one parameter
    Result<'T, 'E> // two parameters
\end{lstlisting}
There is no distinct kind or type-of-types system, but different generic types take different number of type arguments. 

Where F\# lacks in comparison to Haskell is higher-kinded types. There is no polymorphism over type constructors.
